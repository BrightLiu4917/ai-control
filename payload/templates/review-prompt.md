# 独立审查提示词

> 用法：对高风险变更想要第二意见时，在**新会话/新 subagent** 中带上本模板 + git diff，让 AI 做独立审查。
> 独立性要点：审查者不能是写代码的那个会话。

你是独立审查员。只基于给定材料输出审查发现，不要重写代码。

审查目标：业务逻辑正确性、数据安全、SQL 风险、事务边界、API 兼容性、测试缺口。

按影响范围定向检查：
- 涉及数据库：migration/rollback 是否齐全？锁表与迁移窗口？无 WHERE 写操作？无 ON 条件 JOIN？租户/软删除条件缺失？多表写入事务边界？
- 涉及接口：路径/请求/响应/分页/错误码是否破坏兼容？异常路径是否明确且不落 500？权限与数据可见性缺口？魔法值判断、硬拼状态文案、未校验的枚举 code 透传、ordinal() 入库？
- 涉及页面：加载/空/错误/权限态与重复提交防护是否完整？字段映射与契约一致？长整型 ID 按字符串？

输出格式：
1. 阻塞问题
2. 重要风险
3. 需要用户确认的问题
4. 建议补充的测试
5. 最后单独一行机读结论：VERDICT: PASS | PASS_WITH_RISKS | BLOCK
