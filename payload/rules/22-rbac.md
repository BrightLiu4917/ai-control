# RBAC / 访问控制功能规则

## 适用范围

适用于后台菜单、按钮、接口权限、角色授权、外部权限服务、网关鉴权、IAM/SSO、数据范围和越权检查。

## 项目级开关

项目可以通过 `.ai-control/project.env` 的 `ACCESS_CONTROL_MODE` 说明访问控制模式：

| 值 | 含义 |
|----|------|
| `local` | 本服务建设 RBAC，本服务负责角色、权限点、菜单权限、按钮权限、接口权限和数据范围 |
| `external` | 外部系统、网关、IAM 或 SSO 负责访问控制，本服务不维护 RBAC，但必须校验外部传入的身份和权限上下文 |
| `none` | 当前项目或功能不适用访问控制，必须写清原因、暴露面和风险 |
| `pending` | 待确认，进入实现前必须确认 |

## 新后台功能必查

- 本服务是否建设 RBAC。
- 如果本服务不建设，哪个外部系统负责访问控制。
- 外部系统如何把用户身份、角色、权限点、租户或数据范围传给本服务。
- 是否需要菜单权限。
- 是否需要按钮权限。
- 是否需要接口权限。
- 是否区分平台管理、专家、供应商、普通用户等角色。
- 是否需要数据范围隔离。
- 无权限时返回什么错误码和前端状态。
- 越权访问时如何处理和记录审计日志。

## 规则

- 后台管理功能默认不能裸奔，必须明确访问控制方案。
- 本服务建设 RBAC 时，权限码命名必须跟随目标项目已有约定。
- 外部系统负责访问控制时，必须写清责任系统、调用凭证、失败处理和越权处理。
- 当前功能不适用访问控制时，必须写清原因、暴露面和风险。
- 前端隐藏按钮不等于后端已授权，后端或责任系统必须校验。
- 涉及租户、组织、供应商、专家等数据边界时，查询和写入都要校验数据归属。
