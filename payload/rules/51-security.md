# 安全规则

## 必查项
- 身份认证
- 权限校验
- 访问控制模式：本服务 RBAC、外部权限服务、网关/IAM/SSO 或明确不适用
- 本服务 RBAC 角色、权限码、菜单权限和按钮权限，如适用
- 外部访问控制责任系统、凭证传递和失败处理，如适用
- 租户隔离
- 越权访问
- 敏感字段脱敏
- 密码、token、密钥泄露
- SQL 注入
- XSS
- CSRF，如适用
- 文件上传安全
- 审计日志

## 禁止事项
- 禁止向前端暴露异常堆栈。
- 禁止日志记录密码、token、密钥或敏感个人信息。
- 禁止仅依赖前端权限控制。
- 禁止绕过已有鉴权机制。
- 禁止新增后台接口或后台页面时遗漏访问控制说明。
- 禁止只写“需要登录”而不写访问控制方式、责任系统、角色/权限点或明确不适用原因。
- 禁止把密钥写入仓库。

## 后台功能访问控制要求
新增或修改后台、管理端、平台管理、运营后台功能时，OpenSpec 必须说明：

- 访问控制模式：本服务 RBAC、外部权限服务、网关/IAM/SSO 或明确不适用。
- 本服务是否建设 RBAC。
- 责任系统：本服务、网关、IAM、SSO、统一权限服务或其他已确认系统。
- 允许访问的主体，例如平台管理、运营人员、供应商、专家、内部服务或第三方调用方。
- 后端接口权限码或权限点，例如 `admin:user:view`；如果由外部系统负责，写外部权限标识或“不由本服务维护”。
- 前端菜单权限和按钮权限，如适用；如果不适用必须写明原因。
- 无权限、未登录、越权访问的处理方式。
- 是否需要租户、组织、供应商、专家等数据范围隔离。
- 审计日志要求，如登录、审核、导出、删除、权限变更等高风险操作。

## 输出要求
涉及安全边界时必须说明：
- 认证方式
- 访问控制模式和责任系统
- 权限点或外部权限标识
- RBAC 角色和权限码，如适用
- 数据隔离方式
- 敏感字段处理
- 审计和日志
- 剩余风险
