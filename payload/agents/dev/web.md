# 前端实现手册（含 UI 交互设计）

必读规则：`.ai/rules/30-frontend.md` + `31-vue3` 或 `32-react`；涉及接口读 `20-api`；体验规范见 `02-product-ux`。

## 工作流程

1. 定位既有框架、目录、路由、组件库、请求封装和状态管理。
2. 明确 API 契约和前端字段映射。
3. 检查前端请求路径是否符合 `.ai/rules/20-api.md`，禁止拼接路径参数。
4. 实现加载态、空态、错误态、成功态和权限态。
5. Vue / React 页面和组件中的可见文案必须使用中文，包括标题、按钮、表单标签、占位符、提示、介绍文字、空态、错误态、成功反馈、权限态、确认弹窗、表格列名和图表说明。
6. 表单提交前必须按后端 DTO/API 契约和数据库字段约束实现前端校验，包括必填、最大长度、最小长度、格式、枚举、数值范围和数组数量限制。
7. 遵循既有组件和样式系统。
8. 保持最小变更，不做无关重构。
9. 运行类型检查、lint、测试、构建或手动验证。

## 前端文案规则

- 面向用户可见的页面文案必须使用简体中文。
- Vue 组件、React 组件、路由页面、弹窗、抽屉、表单、表格、筛选项、菜单、按钮、Tooltip、空态、错误态、加载态、成功态、权限态和介绍说明禁止使用英文占位文案。
- 英文字段名、API 字段、代码变量、组件名、类名、枚举值、埋点 key 和第三方库配置可以保留英文，但不得直接作为用户可见文案输出。
- 确需展示英文品牌名、协议名、产品名或专有名词时，必须保留原名，并优先配中文解释。
- 发现既有页面存在英文用户文案时，当前改动范围内应同步改为中文；范围外英文文案应列为后续待处理项。

## 表单校验规则

- 前端表单校验必须和后端验证层保持一致；后端 DTO、Request、Form、Validator 或注解中必填的字段，前端也必须标记必填并阻止提交。
- 前端输入长度必须参考数据库字段长度、后端验证注解和 API 契约；例如 varchar 长度、文本最大长度、手机号/身份证/邮箱等固定格式。
- 前端不能放宽后端约束；如后端最大长度为 64，前端最大长度不得大于 64。
- 前端可以更早给出友好提示，但不能替代后端校验；后端仍必须做完整校验。
- 如果数据库字段长度、后端 DTO 校验和 API 契约不一致，必须停止并询问，不能自行选择一个值。
- 表单校验提示必须使用简体中文，并说明用户该如何修正。
- 新增或修改提交表单时，输出中必须说明字段校验来源：数据库字段、后端验证层、API 契约或用户确认规则。

## 精准修改、代码精简与无效代码清理

通用规则见 `.ai/rules/01-code-change.md`，必须逐项遵守。前端栈补充：

- 即使 IDE 显示 `0 usages` 也不能直接删除：路由页面、菜单入口、权限配置、动态组件、自动注册组件、状态模块、API 字段映射、导入导出字段和对外兼容字段。
- 既有疑似 dead code 的引用检查必须额外覆盖：路由配置、菜单权限、动态注册和构建入口。
- 简单 className 拼接不要拆成空壳组件。
- 删除前端组件、hook、路由、状态或工具函数后，必须运行 lint、类型检查、测试、构建或手动验证，无法验证时说明残留风险。

## 工作流程

1. 明确用户入口、任务目标和主路径。
2. 梳理异常流程、失败反馈、权限态和空数据场景。
3. 检查表单校验、重复提交和高风险确认。
4. 优先复用既有组件、颜色、图标、间距和布局约定。
5. 检查页面、组件、按钮、表单、提示、介绍文字、空态、错误态、成功态和权限态等用户可见文案是否使用简体中文。
6. 检查文本溢出、组件重叠、多视口和状态展示。
7. 将需要前端实现的事项交给 开发工程师（`agent-dev`）。

## 禁止事项

- 禁止未确认引入新设计系统。
- 禁止无意义装饰。
- 禁止卡片套卡片。
- 禁止文本溢出、遮挡或按钮文字放不下。
- 禁止在用户可见文案中使用英文占位或英文说明，除非是已确认的品牌名、协议名、产品名或专有名词。
